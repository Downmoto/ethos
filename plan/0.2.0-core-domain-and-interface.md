# 0.2.0: Core domain and interface

## Delivery

Extend the 0.1.0 daemon with portable workspace directories, nested projects, saved agent definitions, persistent sessions, and an authenticated HTTP API. A remote client can manage these resources through a standard HTTPS proxy. No model request, conversation turn, tool, or automation runs in this milestone.

0.1.0 is the prerequisite. Its instance lock, configuration reload, lifecycle coordinator, maintenance gate, health reporting, and host-only control socket remain the entry points. Register a workspace registry service and the API with that coordinator. The API depends on the workspace registry, so startup opens workspaces before the listener admits requests and reverse-order shutdown drains HTTP requests before workspace databases close. An invalid individual workspace remains isolated without failing the registry service.

## Repository and dependency contract

Keep the Cargo monorepo and the single `ethos` executable. Add `crates/ethos-domain` for workspace, project, agent-definition, and session rules. Extend `ethos-core` with workspace discovery and instance credential state. Put HTTP routing and JSON conversion in `crates/ethos/src/api/`. `ethos-domain` must not depend on Axum or the CLI; the binary translates HTTP requests into domain operations.

Add Axum for HTTP, `getrandom` for credential bytes, and `sha2` for credential hashes and stable file revisions. Use existing Tokio, Serde, TOML, rusqlite, UUID, and tracing dependencies. Use one connection per workspace, guarded by a per-workspace mutation lock and called through short `spawn_blocking` operations. Bound queued operations per workspace so blocked SQLite calls cannot consume an unlimited number of blocking threads. Track accepted database operations and drain them before closing connections or releasing workspace locks. A running `spawn_blocking` call cannot be cancelled: if the instance shutdown deadline expires before it finishes, leave the clean marker unset and terminate the process without releasing ownership for another process to acquire while that call can still write. Keep HTTP request bodies bounded. Add no provider, ARE, AAE, plugin, or SDK crate yet.

## Storage and ownership contract

All workspace directories live under the instance home, as chosen by the owner. Their relative layout is:

```text
~/.ethos/
  config.toml
  state.sqlite                 # instance state and one active API credential hash
  workspaces/                  # 0700; created by the 0.2.0 upgrade
    <workspace-uuid>/          # 0700; portable as one directory
      workspace.toml           # 0600; ID, display name, schema version
      workspace.lock           # 0600; held while this instance owns the workspace
      workspace.sqlite         # 0600; sessions and append-only history
      agents/
        <agent-uuid>.toml      # saved agent definitions
      projects/
        default/               # hidden internal project for unscoped sessions
          project.toml
          files/
        <project-uuid>/
          project.toml
          files/
```

The directory name and manifest ID must match. IDs are immutable UUIDs except the reserved `default` project ID. Names are mutable labels and need not be unique. Use IDs in references and URLs; never derive a path from a user-supplied name. Workspace data contains no instance-specific absolute path or credential. A workspace copied into another stopped instance's `workspaces/` directory is discovered on next startup; an existing directory with that ID must never be overwritten. Copying a live workspace is not a supported transfer; later backup/export work supplies a consistent live snapshot.

The daemon discovers child directories at startup, validates their names, then acquires each workspace lock before opening or validating mutable state. Check ownership, modes, manifest IDs, database schema and integrity before exposure. A physical workspace directory owned by another instance, invalid manifest, or corrupt database is isolated and recorded as a degraded cause; other workspaces remain available. Separate copies are independent even when they retain the same workspace ID. Never silently recreate missing files in an existing workspace. A clean shutdown closes each database and releases each workspace lock after its work has stopped. Do not use WAL in this milestone: one database connection per workspace and rollback journalling keep a stopped directory copy self-contained. Revisit journal mode if measured concurrency requires it.

Create a workspace in a temporary sibling directory, fully write and sync its manifest, default project, and database, then rename it to its UUID and sync the parent `workspaces/` directory before returning success. On restart, discard only an identifiable incomplete temporary creation after recording a diagnostic. Create project and agent files with a same-directory temporary file, sync, rename, and parent-directory sync. Human edits to TOML are read and validated before use; an invalid edited definition is reported for that resource without rewriting it. All API updates take the workspace mutation lock, re-read the current file, compare its revision, then replace it atomically.

## Domain contract

| Resource | Required fields | 0.2.0 operations |
|---|---|---|
| Workspace | Immutable ID, display name, schema version | Create, list, get, rename |
| Project | Workspace ID, immutable ID, display name | Create, list, get, rename |
| Agent definition | Workspace ID, immutable ID, display name, model reference, options table, enabled capability IDs | Create, list, get, replace |
| Session | Workspace ID, project ID, immutable ID, agent ID, creation time, last activity time, revision | Create, list, get; internal history append |

The default project is created with every workspace, omitted from project lists, and cannot be renamed or deleted. Session creation without `project_id` uses it; every stored session has an actual project ID. A session may select only an agent from its own workspace. Projects isolate their sessions and files. Agents belong to a workspace and can be selected by sessions in any project in that workspace. No cross-workspace reference is accepted. A project does not implicitly authorise access to another project's session or files.

Agent files use a strict, versioned TOML envelope: `schema_version`, `id`, `name`, `model = { provider, name }`, `options = {}`, and `capabilities = []`. In 0.2.0, provider and model are nonempty identifiers, options must be empty, and capabilities must be empty; 0.3.0 and 0.4.0 extend and validate those fields when execution and capabilities arrive. The workspace is the owner of future capability configuration. Do not create a generic plugin registry or accept unimplemented capability IDs now. Existing agent files must retain their ID across edits. An invalid agent file does not make unrelated agents unavailable.

Use the workspace database for sessions and immutable history rows, beginning at `PRAGMA user_version = 1`. Its first migration creates `sessions(id TEXT PRIMARY KEY, project_id TEXT NOT NULL, agent_id TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, revision INTEGER NOT NULL CHECK (revision >= 0))` and `session_events(session_id TEXT NOT NULL REFERENCES sessions(id), sequence INTEGER NOT NULL, kind TEXT NOT NULL, payload_json TEXT NOT NULL, created_at TEXT NOT NULL, PRIMARY KEY (session_id, sequence))`. Persist times as UTC RFC 3339 strings. Validate project and agent ownership in the domain layer before insert because their definitions live in TOML files. The domain layer appends an event and increments session revision in one transaction, rejecting an expected-revision mismatch. There is no public message-append or turn endpoint yet, so clients cannot forge assistant or tool messages. 0.3.0 defines event kinds and the turn lifecycle. Do not store transcript content in instance `state.sqlite`.

## Network and credential contract

Add `[api] listen = "127.0.0.1:8765"` to instance TOML. The value is a loopback socket address, must be unique among running instances, and requires restart to change. Reject non-loopback addresses in this milestone. Bind the configured listener as a critical lifecycle service; a bind failure prevents readiness. A same-host HTTPS reverse proxy, including Tailscale Serve, provides remote access. The proxy must share Ethos's network namespace to reach `127.0.0.1`; separate containers with separate network namespaces cannot use each other's loopback address. HTTP is the local upstream protocol; Ethos does not terminate TLS in 0.2.0. Keep host-only administration on the Unix socket.

The owner creates the instance-wide API credential with `ethos --home PATH api token create` through the host CLI. Generate 32 random bytes from the operating system, encode them as `e1_` plus lowercase hex, store only their SHA-256 hash in `state.sqlite`, and print the token once to the invoking terminal. `api token rotate` replaces the active hash in one transaction and prints a new token once. There is one active credential; rotation invalidates the old one immediately. The CLI never logs the token. If output fails after commit, the owner can rotate again. When the daemon is running, these commands use the protected local control socket; when stopped, they acquire the instance lock before writing the database. Creation fails if a credential already exists.

Every `/v1` request requires `Authorization: Bearer <token>`, including reads. Reject missing, malformed, or invalid credentials with the same generic `401` response. Compare the computed hash without exposing the stored hash or token. Never accept credentials in query parameters. No API route installs plugins, changes instance configuration, reads secrets, or calls host maintenance operations. Do not enable browser CORS by default; the Vox browser-versus-backend choice is resolved before its 0.3.0 integration. A reverse proxy must forward `Authorization` and provide HTTPS on the client-facing side.

Define a versioned JSON API with these routes:

| Route | Behaviour |
|---|---|
| `GET /v1/health` | Authenticated liveness, readiness, degraded causes, and API version. |
| `GET, POST /v1/workspaces` | List available and isolated workspaces; create a workspace. |
| `GET, PATCH /v1/workspaces/{workspace_id}` | Read or rename one workspace. |
| `GET, POST /v1/workspaces/{workspace_id}/projects` | List visible projects; create one. |
| `GET, PATCH /v1/workspaces/{workspace_id}/projects/{project_id}` | Read or rename one project. |
| `GET, POST /v1/workspaces/{workspace_id}/agents` | List or create saved agents. |
| `GET, PUT /v1/workspaces/{workspace_id}/agents/{agent_id}` | Read or replace an agent definition. |
| `GET, POST /v1/workspaces/{workspace_id}/sessions` | List or create sessions, filterable by project. |
| `GET /v1/workspaces/{workspace_id}/sessions/{session_id}` | Read session metadata and its current revision. |

Use these JSON write shapes: workspace and project create `{ "name": "..." }`; rename `{ "name": "..." }`; agent create/replace `{ "name": "...", "model": { "provider": "...", "name": "..." }, "options": {}, "capabilities": [] }`; session create `{ "agent_id": "...", "project_id": null }`, where null or omission selects the hidden default. Servers assign IDs, timestamps, and revisions. Responses include the resource ID and its parent IDs, plus the writable fields; session responses expose `project_id: null` for the hidden default while storage retains `default`. Reject client-supplied IDs, timestamps, unknown fields, and nonempty 0.2.0 options or capabilities. Every file-backed GET and successful mutation returns an `ETag` header.

Create responses return `201` and a `Location` header. List responses have a stable `{items, next_cursor}` envelope, return at most 100 items ordered by immutable ID, and accept `?cursor=<last-id>` for the next page; `next_cursor` is null only on the last page. IDs, timestamps, and field names use one documented JSON shape. Invalid JSON and fields return `400`; missing resources return `404`; invalid domain values return `422`; isolated workspace returns `503` with its stable cause. All errors use `{error:{code,message}}`. No endpoint returns a filesystem path. The agent PUT and rename PATCH requests require `If-Match` with a quoted revision derived from the current file bytes. Missing precondition returns `428`; a mismatch returns `412`. Sessions expose their integer revision for later turn APIs.

Each mutating application request acquires a 0.1.0 admission permit before domain work and holds it through the mutation. If work moves to `spawn_blocking`, that operation owns the permit until it finishes, even if the HTTP client disconnects. Maintenance or shutdown closes the gate atomically against new permits; authenticated reads and health remain available during maintenance, while new creates and updates return `503 maintenance`. Already admitted requests finish or fail under the shutdown deadline. On shutdown, stop accepting new HTTP requests, drain accepted requests and tracked database operations, then close workspace databases and release their locks. If the deadline expires with a blocking database operation still running, preserve the dirty instance marker and terminate the process; do not release locks while that operation could still write. Multiple connected clients may read and mutate through the one daemon; each workspace serialises conflicting file writes and its SQLite transactions.

## Implementation sequence

Complete each slice and its check before moving to the next.

### 1. Monorepo and instance upgrade

- [ ] Add `ethos-domain`, its module boundaries, and the three new direct dependencies. Keep `ethos-core` independent of Axum. Update the Cargo lockfile and Linux CI.
- [ ] Add the `[api]` TOML section, default loopback address, strict validation, and restart classification to 0.1.0 config handling. Test rejected mixed reloads leave the active snapshot unchanged.
- [ ] Add a transactional `state.sqlite` migration from `user_version = 1` to `2` with `api_credential(singleton INTEGER PRIMARY KEY CHECK (singleton = 1), token_hash BLOB NOT NULL CHECK (length(token_hash) = 32))`. Only the host CLI creates the row; rotation updates it. Test that a second row cannot be inserted. Upgrade a populated 0.1.0 home without changing its instance ID, clean marker, or run generation. Reject a newer or corrupt schema.
- [ ] Create `workspaces/` with mode `0700` during the upgrade. Make a second upgrade a no-op. Run all 0.1.0 checks before adding domain behaviour.

### 2. Workspace creation and discovery

- [ ] Implement workspace manifest parsing, UUID and path checks, mode checks, a held `workspace.lock`, and the directory layout above. Implement the version-1 workspace SQLite migration and create the database with its schema in the temporary workspace before publication. Use one owner object that retains the file lock and database connection until shutdown.
- [ ] Implement the temporary-directory creation transaction, including a sync of `workspaces/` after the final rename, and the startup scan. Keep instance-relative IDs in all persisted references. Report invalid or busy workspaces as degraded causes without losing the healthy ones.
- [ ] Test two workspaces in one instance, separate instances owning separate copies, a second physical owner being rejected, corrupt manifest, missing database, and forced death during creation. Copy a stopped workspace directory into another instance home and verify discovery with its original ID and data.

### 3. Projects and persistent definitions

- [ ] Implement hidden default-project creation and resolution. Add visible project create/list/get/rename. Validate workspace ownership for every lookup; refuse `..`, symlinks, and IDs outside the expected format.
- [ ] Implement strict agent TOML read/write and the empty options/capabilities rule. Validate nonempty provider and model identifiers and an agent's workspace when creating a session. Defer provider-profile and model resolution until 0.3.0.
- [ ] Implement file revisions and compare-and-replace writes under the per-workspace mutation lock; HTTP `If-Match` parsing follows in slice 6. Test stale writes from two domain callers, direct human edits between reads, interrupted atomic replacement, and one malformed agent file alongside a valid agent.

### 4. Session database and invariants

- [ ] Open each workspace database using the version-1 migration from slice 2, with foreign keys and unique event sequence. Confine each `rusqlite::Connection` to blocking work; never hold an async runtime thread while waiting on SQLite. Bound and track pending operations, report overload without changing state, and drain accepted operations before connection close.
- [ ] Implement session create/list/get with explicit project ownership and the hidden default. Add the internal append-event transaction and expected-revision check for 0.3.0 to consume.
- [ ] Test session creation in each project, omitted project selection, invalid cross-workspace agent/project IDs, event sequence under concurrent writes, restart persistence, and workspace copy preserving history.

### 5. Host credential management

- [ ] Implement OS-random token generation, hex encoding, SHA-256 storage, and atomic create/rotate. Extend only the host control socket with `api_token_create` and `api_token_rotate`; support stopped-instance commands under the lock.
- [ ] Ensure no token appears in logs, errors, status, config show, or database reads. Test first creation, duplicate creation, rotation invalidation, malformed tokens, output failure recovery by rotation, and two instances with different credentials.

### 6. HTTP service and API

- [ ] Register the workspace registry before the Axum listener and declare the API's dependency on it. Isolate invalid individual workspaces. Authenticate before routing to resource handlers; cap body size and reject unknown request fields. Shut down under the lifecycle deadline by closing HTTP admission, draining accepted requests and database operations, then stopping the workspace registry. Extend the 0.1.0 `test-fixtures` feature with a stalled blocking database operation to verify deadline expiry leaves a dirty marker and releases locks only when the process exits.
- [ ] Implement the table of `/v1` routes and one error mapping. Map isolated workspaces and maintenance to stable errors. Use domain calls for all lookups and writes; no handler constructs a disk path from raw request text.
- [ ] Run client-level tests over loopback TCP: missing/wrong token, current token, host-only route absence, CRUD, stale `If-Match`, pagination past 100 records, two concurrent clients, a mutation racing maintenance admission, orderly shutdown with an in-flight request, deadline expiry during blocking database work, and restart. Run one release smoke test through an HTTPS reverse proxy and verify it forwards `Authorization`.

### 7. Documentation and gate

- [ ] Document the instance upgrade, workspace copy procedure, TOML and JSON schemas, each API route and error, token creation and rotation, proxy setup, and backup limitation for live workspaces. The deployment guide must show Tailscale Serve forwarding to `127.0.0.1:8765`, state the shared network namespace requirement, and explain why separate default container namespaces cannot reach that loopback listener. Include a `curl` walkthrough using a project, agent, and session.
- [ ] Run format, Clippy, workspace tests, and locked release build as in 0.1.0. Record a process test where one client creates a workspace and another reads its project and session after reconnecting. Tag `0.2.0` only when the checks below pass.

## Exit gate

Starting from a valid 0.1.0 home, the daemon upgrades without data loss. The host CLI issues a credential; an authenticated client reaches the API through HTTPS proxy and creates a workspace, visible project, saved agent, and session. The session belongs to its selected project or the hidden default. A second client reads the same persisted resources after restart. Stale agent edits fail, a damaged workspace is isolated, and a copied stopped workspace loads in another instance with its ID and session history intact. Unauthenticated requests and network attempts at host-only operations fail. No model execution is required.
